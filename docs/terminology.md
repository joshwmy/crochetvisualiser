# Terminology

Phase 1 uses **US crochet terminology exclusively**. UK terminology (where,
notably, US single crochet == UK double crochet) is a modelled-but-unused
enum value (`domain.enums.Terminology.US` is the only member) — adding UK
support later requires a mapping layer in the renderer, not a schema
change.

## Abbreviations used in generated patterns

| Abbreviation | Meaning |
|---|---|
| `sc` | single crochet |
| `hdc` | half-double crochet |
| `st` / `sts` | stitch / stitches |
| `MR` | magic ring (adjustable ring) |
| `inc` | increase (2 or more stitches worked into one stitch) |
| `dec` | decrease (2 or more stitches worked together as one) — modelled in the schema but not generated by any Phase 1 template |
| `*...* around (N times)` | repeat the enclosed instructions N times to complete the round |
| `(N)` | stitch count at the end of the round |
| BLO | back loop only |
| FLO | front loop only |

## Domain vs. rendering vocabulary

The structured pattern (`domain/operations.py`) never stores natural-language
abbreviations — it stores typed enum values (`StitchFamily.SC`,
`LoopPlacement.BACK_LOOP_ONLY`, etc.). The renderer
(`rendering/text_renderer.py`) is the only place abbreviations are produced,
via a fixed lookup table (`_STITCH_LABELS`). This means terminology can be
extended (e.g. adding UK labels) without touching the domain model, engine,
or validator — exactly the separation required so "the renderer may improve
wording, but it must not alter stitch totals, operations, round count,
gauge calculations, dimensions, or template parameters."
